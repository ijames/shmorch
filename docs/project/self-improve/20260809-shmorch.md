#### Proposal 1: EXPECTED_DOCS is missing `docs/project/plan`
**Pattern:** `workflows/auto-update.md`'s scaffold-reverse check (Step 2.2, line 160)
hardcodes `EXPECTED_DOCS` as the canonical directory list used to flag any project
directory under `docs/` that isn't recognized:
```
EXPECTED_DOCS="docs docs/project docs/project/tracks docs/project/schedule docs/project/process docs/product docs/product/strategy docs/product/design docs/product/features docs/product/decisions docs/technology docs/technology/architecture docs/technology/development docs/technology/decisions docs/reference docs/reference/instructions docs/reference/research docs/inbox"
```
`docs/project/plan` is absent. This is not this-repo-specific — `templates/docs/project/plan`
exists as the scaffold template shipped to every consumer project, and `docs/project/plan/`
is referenced as the canonical backlog location in ~20 workflow files (`build.md`, `commit.md`,
`curate.md`, `design.md`, `navigate.md`, `orient.md`, `prioritize.md`, `resume.md`, `spec.md`,
`sprinter.md`, `vacuum.md`, `wrap.md`, `commands/status.md`, etc.) plus `workflows/init.md`
line 40. So every project that has run `init` (or `sync`) and has a live `docs/project/plan/`
directory will hit a false "UNLISTED DIR: docs/project/plan" on the next `auto-update` scaffold
check — the exact opposite of what the check is for.
**Frequency:** Structural — fires on every `auto-update` run against any project with the
canonical `docs/project/plan/` directory (confirmed live in this repo, 33+ files, referenced
throughout `session.md`, `wrap.md`, and other workflows). Distinct from — and not fixed by —
the currently-open PR #99, which added `docs/technology/infrastructure`,
`docs/project/prioritizer`, and `docs/project/documentarian` to the same list but left
`docs/project/plan` out.
**File:** `workflows/auto-update.md`, line 160
**Change:** Add `docs/project/plan` to the `EXPECTED_DOCS` string:
```
EXPECTED_DOCS="docs docs/project docs/project/plan docs/project/tracks docs/project/schedule docs/project/process docs/product docs/product/strategy docs/product/design docs/product/features docs/product/decisions docs/technology docs/technology/architecture docs/technology/development docs/technology/decisions docs/reference docs/reference/instructions docs/reference/research docs/inbox"
```
(Bundle with PR #99 if still open, since both touch the same line and would otherwise conflict.)
**Improvement:** Removes a guaranteed false positive from the scaffold-drift check on every
project using the canonical backlog directory; stops developers from being asked whether
`docs/project/plan` is "project-specific or canonical" when it's unambiguously canonical.

#### Proposal 2: `docs/project/plan/index.md`'s Current Task references a directory that no longer exists
**Pattern:** `docs/project/plan/index.md` frontmatter says `updated: 2026-07-24`, but its
"Current Task" section (lines 17-26) still describes bringing "`docs/state/` (root files +
all 14 track folders)" to clean shape — `docs/state/` was the *pre-migration* path name.
The very next section, "Completed" (line 48), records that the "Docs taxonomy redesign"
replacing `docs/state/` with the current `docs/project/` (etc.) tree closed on that same date,
2026-07-24. So the file simultaneously claims (a) the rename that eliminated `docs/state/`
is done, and (b) there's active work still targeting `docs/state/` by name. Since then, 8+
timelog-visible sessions and ~10 PRs have landed (semver migration #92/#93, `stack.md`
template restore #90, wrap-friction/self-improve-cap fixes #86/#87, cross-repo inbox
discipline #97, self-improve scope #98, PR #99 open) with no corresponding update to
Current Task — none of that work is reflected here, and "Two other processes were active
... 2026-07-21" (messaging-provider design, self-improve) is now three-plus weeks stale.
`workflows/wrap.md` line 101 only updates Current Task "if the focus moved," which is a
judgment call the last several sessions apparently didn't make even as the underlying
directory the task refers to was deleted.
**Frequency:** Single artifact, but a 3+ week gap spanning 8+ sessions/PRs without the
"if focus moved" trigger firing — the conditional check isn't robust to project-name-level
drift (a referenced path disappearing) unless a session explicitly notices.
**File:** `workflows/wrap.md`, Step ~101 (Current Task update) — and, as immediate content
fix, `docs/project/plan/index.md` itself.
**Change:**
1. Content fix (do now, docs-only, no VERSION bump): rewrite `docs/project/plan/index.md`'s
   Current Task section — drop the stale `docs/state/` backfill description (superseded by
   the taxonomy redesign closing) and either restate the remaining live thread (the
   `tracks/20260717-state-store-shape/` frontmatter+backlinks backfill, if still open) or
   mark Current Task empty/"none active" if it isn't.
2. Process fix: in `workflows/wrap.md`'s Current Task step, add an explicit staleness check
   alongside the "if focus moved" check: grep Current Task's prose for any path token (e.g.
   `docs/state/`, other since-renamed paths) against the actual current tree, and flag if a
   referenced path no longer exists — not just "did focus move."
**Improvement:** Prevents the plan index from asserting active work against paths that were
already deleted by a *closed* item two lines below it in the same file — a self-contradiction
that undermines trust in `plan/index.md` as the authoritative "what's active" pointer.
