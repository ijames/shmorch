### Self-Improve Proposals — 2026-07-07 | Project: appadd

#### Proposal 1: `timelog.sh` should guard against double SESSION_START

**Pattern:** The timelog has 20 instances of two `SESSION_START` entries appearing back-to-back with no intervening `SESSION_END` — an append-only ledger with broken session pairing. Example (current session, lines 328–330):
```
[2026-07-07 17:13:39] SESSION_START | shmorch update 20260621.01->20260707.04, then orient
[2026-07-06 22:18:57] SESSION_START | new session
[2026-07-07 17:24:23] SESSION_START | Sprint 3b: GEO foundation, legal, revenue surface
```
(Note also the backdated timestamp on the middle entry — a symptom of the same root cause: something other than the normal `go`/`resume` entry point is stamping `SESSION_START` directly.)

This is distinct from the already-working "auto-wrapped on reentry" recovery path (21 clean instances found, each a proper END-then-START pair) — those are `go.md`'s Catch-Up Wrap doing its job via `check-session-state.sh`. The 20 double-starts are cases where that check was bypassed entirely: compaction reentry, ad hoc "new session" utterances, or any path that calls `timelog.sh SESSION_START` without routing through `go`/`resume` first. `check-session-state.sh` and the Catch-Up Wrap logic are correct — they're just not always in the call path.

**Frequency:** 20 occurrences across 2026-05-17 through 2026-07-07 (this session), roughly 2–3 months of continuous recurrence — well past the 2-occurrence pattern threshold.

**File:** `~/.claude/skills/shmorch/tools/timelog.sh`

**Change:** Move the INTERRUPTED guard into `timelog.sh` itself so it applies no matter which workflow path triggers a `SESSION_START`, not just the `go`-initiated one:
```bash
if [ "$EVENT" = "SESSION_START" ] && [ -f "$ROOT/docs/state/timelog.md" ]; then
  LAST=$(grep "SESSION_" "$ROOT/docs/state/timelog.md" 2>/dev/null | tail -1 || true)
  if [[ "$LAST" == *"SESSION_START"* ]]; then
    AUTO_TS=$(date '+%Y-%m-%d %H:%M:%S')
    echo "[$AUTO_TS] SESSION_END | auto-wrapped (guard: consecutive SESSION_START)" >> "$ROOT/docs/state/timelog.md"
  fi
fi
```
This makes the ledger self-healing at the point of writing, instead of relying on every caller to check state first.

**Improvement:** Timelog pairing stays structurally sound (every START has a matching END) regardless of entry path — `go`, `resume`, compaction reentry, or an ad hoc "new session" — closing the gap that `check-session-state.sh` alone doesn't cover because it's only consulted by `go.md`.
