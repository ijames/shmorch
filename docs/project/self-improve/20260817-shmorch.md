### Self-Improve Proposals — 2026-08-17 | Project: shmorch

#### Proposal 1: Detect session.md drift from merged PRs in go.md's SELF branch

**Pattern:** session.md repeatedly falls behind actual merged work, requiring a
retroactive "catch-up" narrative entry instead of a real-time log. This is distinct
from the existing INTERRUPTED-session catch-up (Step 3's CW-1..CW-8), which only fires
when a session ended without a `SESSION_END` stamp — these drifts happened even with
clean session boundaries; the *narrative* in session.md simply wasn't updated to match
commits that landed on `main`.

**Frequency:** 4 occurrences over ~10 weeks:
- session.md "2026-07-17 ... catch-up (several sessions never logged here since 2026-07-14)"
- session.md "2026-08-01 to 2026-08-04 — catch-up (logged after the fact)"
- session.md "2026-08-04 to 2026-08-05 — catch-up (logged after the fact)"
- session.md "Since last entry — merged, undocumented — 2026-08-14 (via `/shmorch touch`)":
  PRs #106-#109 merged after the 2026-08-10 entry with no session.md update in between.

Notably the 08-14 instance happened *after* `core/git-discipline.md`'s "Before pushing a
branch or merging its PR" rule (added 2026-08-10) already required session.md to be
current before the final push/merge — so the rule alone isn't preventing drift; `touch`
is currently the after-the-fact recovery, not a proactive catch.

**File:** `workflows/go.md`, Step 1 (SELF branch, right after the existing "SELF inbox
check" block at lines 41-48).

**Change:** Add a parallel check that compares session.md's last dated entry against
`git log` on `main` since that date, e.g.:
```bash
LAST_ENTRY=$(grep -oE '^\#\# .*— [0-9]{4}-[0-9]{2}-[0-9]{2}' docs/project/session.md | head -1 | grep -oE '[0-9]{4}-[0-9]{2}-[0-9]{2}')
git log --since="$LAST_ENTRY" --oneline --merges main 2>/dev/null
```
If merges exist after the last logged date, surface: "session.md's last entry is
$LAST_ENTRY but N PR(s) merged since — run `/shmorch touch` before continuing?" — same
non-blocking style as the existing inbox check.

**Improvement:** Catches the drift at the next session-start instead of accumulating
across multiple sessions into a multi-PR retroactive catch-up entry — the exact
recurring shape seen 4 times.
