### Self-Improve Proposals — 2026-07-17 | Project: appadd

#### Proposal 1: Reconstruction-from-git-log doesn't update track status fields
**Pattern:** Sessions routinely end without `/shmorch wrap` running, forcing the next session to reconstruct history from git log (`session.md` marks these `_(reconstructed from git log — session ended without wrap)_`). The reconstruction captures commits and decisions but repeatedly misses updating the affected track's `index.md` status field, which then goes stale until a documentarian sweep catches it days or weeks later.
**Frequency:** 14 "session ended without wrap" reconstructions in `session.md` (grep count); at least 3 of these produced a stale-status finding later fixed by a documentarian pass or a subsequent session's manual catch:
- `session.md` 2026-06-19 documentarian entry: fixed `20260618-intro-hook`'s "self-contradictory 'Closed... awaiting PR' status," and found `tracks/index.md` tracking only 10 of 37 track dirs.
- `session.md` 2026-06-29 entry: "Track `20260628-understand-section`: code shipped (PR #78 merged), track status field still says 'Open — Intent + Spec' — needs updating."
- `session.md` 2026-07-07 entry: corrected a stale status line in `sprint.md` Section 4 and a stale memory that claimed test failures were still open when `plan.md` already showed them closed.
**File:** `.shmorch/workflows/wrap.md` (or skill default `$SHMORCH_HOME/workflows/wrap.md` if no project override) — the reconstruction/catch-up path specifically.
**Change:** Add an explicit step to the catch-up-wrap procedure: when reconstructing a skipped session from git log, grep the commit messages/diffs for track directory names touched (`docs/state/tracks/*/index.md` or PR titles referencing a track slug) and check each such track's `Status:` field against what the commits imply (merged PR → shipped; if status still says Open/Intent, flag or update it) before writing the session.md entry. Don't let the reconstruction stop at "what commits happened" — require it to close the loop on any track status the commits obviously changed.
**Improvement:** Removes the repeated need for a full documentarian sweep to catch stale track statuses that a same-session catch-up wrap could have fixed immediately, and prevents `plan.md`/memory drift (like the 2026-07-07 stale-test-failure memory) that comes from trusting an out-of-date status field.

#### Proposal 2: go/resume orientation re-reads full state files every session, cost flagged twice without resolution
**Pattern:** The `go`/`resume` orientation step reads all of `session.md`, `plan.md`, `timelog.md` in full each session. This was flagged as a cost concern, "fixed" once, and flagged again three months later as still unresolved.
**Frequency:** 2 occurrences spanning the full history:
- `session.md` 2026-07-07: "Goal of this sync was reduced context usage on future `/shmorch go` invocations... Not yet verified — confirm on next session's `go` that context footprint is visibly lighter."
- `session.md` 2026-07-17 (latest): "(3) an open question about shmorch's own context-scoping as the project scales (full state-file reads vs. narrow task-scoped slices) — logged as memory `feedback_shmorch_context_scoping.md`, unresolved, for a future shmorch-design conversation."
The verification promised on 07-07 never happened, and the same concern resurfaced 10 days later as a still-open question — evidence the intervening skill update didn't actually change the orientation read pattern (this project's own `session.md` is now 80KB+ and `timelog.md` 27KB+, read in full on `go`).
**File:** `$SHMORCH_HOME/workflows/go.md` (and `core/context.md` if the JIT-loading doctrine lives there).
**Change:** Change the orientation step's read strategy from "read `session.md`/`timelog.md` in full" to "read `session.md`'s latest entry + `timelog.md`'s last N (e.g. 20) lines by default; only read further back if the current track's `index.md` or `plan.md` current-task section references something not covered by that window." This turns the promised 07-07 improvement into an actual mechanical change instead of a hoped-for side effect of an unrelated sync.
**Improvement:** Makes the context-cost fix concrete and testable (window size is checkable) instead of an aspiration that silently failed to land, and stops the same complaint from re-surfacing as a fresh "open question" every few months.
