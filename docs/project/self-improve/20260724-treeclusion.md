### Self-Improve Proposals — 2026-07-24 | Project: treeclusion

#### Proposal 1: `stop.sh` wrap-reminder never fires because its grep pattern doesn't match the plan.md template's actual format
**Pattern:** `$SHMORCH_HOME/tools/stop.sh` only prints the "run /shmorch wrap before ending session" reminder when `docs/state/plan.md` contains the literal substring `| In progress |` (a markdown-table-cell style). But the actual plan.md template (`$SHMORCH_HOME/templates/docs/state/plan.md`) and every plan.md this project ever produced use a different convention: `STATUS: PENDING` / `STATUS: IN PROGRESS` (see `orient.md:136` — "Update plan.md status to 'In progress'" — and `intake.md:40` — "STATUS: PENDING"). The grep target and the actual writers of plan.md have never agreed on a format, so the condition in stop.sh is dead code: it will never match a plan.md produced by the skill's own workflows.
**Frequency:** 3/3 session ends in this project's timelog (`2026-07-21 20:21:23`, `2026-07-21 20:49:05`, and the `2026-07-24 10:34:43` entry) are all `SESSION_END | auto-closed by stop hook`, none preceded by an explicit `/shmorch wrap` (no `WRAP` phase entry appears anywhere in the timelog). plan.md's current content is `STATUS: IN PROGRESS` (docs/state/plan.md), which does not contain `| In progress |`, so the reminder silently never printed.
**File:** `$SHMORCH_HOME/tools/stop.sh` (the grep condition), and/or `$SHMORCH_HOME/templates/docs/state/plan.md` / `workflows/orient.md` (the format contract)
**Change:** Make stop.sh's active-track check match the format the templates and workflows actually emit: `grep -qE "STATUS:\s*IN PROGRESS"` instead of `grep -q "| In progress |"`. Alternatively, pick one canonical status-marker format and update whichever side is wrong — but stop.sh should not silently no-op on the template's own output.
**Improvement:** The wrap reminder will actually fire when a track is open at session end, closing the gap that let `docs/development/decisions.md`, `anti-decisions.md`, `notes.md`, and `tech-stack.md` sit as unfilled templates through 15+ commits of real architectural work (Frame-component nested-DOM model, ResizeObserver-based gutter registry replacing CSS, one-bar-per-link simplification, React+Vite stack confirmed) — this project's wrap workflow (which would sync those files) has never once run.

#### Proposal 2: no mechanism nudges mid-track decisions into `decisions.md` before wrap
**Pattern:** Real architectural decisions were made and only recorded in `docs/state/tracks/20260722-stretchtext-mockup/index.md` work-log entries (e.g. "gutter rebuilt as a measured ResizeObserver registry independent of content DOM," "connector mechanism removed entirely, leaving one continuous bar per expanded link," Vite+React "confirmed working" as the resolved rendering-stack choice per the track's own "What changes" section) — none graduated to `docs/development/decisions.md`, which remains the unfilled template scaffolded at init. `design.md §52` and `orient.md:174` both say to append to decisions.md "when a significant decision is made" (not only at wrap), but nothing enforces or checks this during a build-phase session.
**Frequency:** 8 distinct rounds/versions (v4.0 initial mockup through v5.2 inline links) each contain at least one architectural decision per the track log, none graduated — same root cause as Proposal 1 (wrap never runs) but also a gap even independent of wrap, since the doctrine says decisions should be appended "now," not deferred to wrap.
**File:** `$SHMORCH_HOME/workflows/build.md` (Step area around line 122, "Affected decisions: Does this implementation require a new entry in decisions.md?")
**Change:** This check already exists as a step in build.md but appears to not be getting executed/enforced per-round in this project's actual usage. Consider making it a stronger gate: require the round/commit message or work-log entry to explicitly state "decisions.md: none" or the actual entry added, so silence is visible rather than assumed. (Lower-confidence proposal — the check exists in doctrine; the gap is enforcement, not the rule itself. Recommend pairing with Proposal 1's fix first and re-observing before changing build.md.)
**Improvement:** decisions.md stays populated in real time rather than accumulating as a backlog only visible at wrap (which, per Proposal 1, isn't running anyway).
